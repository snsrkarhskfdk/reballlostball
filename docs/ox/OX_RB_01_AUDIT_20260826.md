## Confirmed finding · P1 maintenance / accidental-entrypoint risk

The repository simultaneously contains:

- `app.js` ≈ 360 KB
- `app-current.js` ≈ 344 KB
- `index.html`
- `index-current.html`

The existing lint/build-check scripts validate the shipping `app.js`/`index.html`, but did not fail if a shipping source accidentally referenced one of the legacy `*-current` entrypoints. `AGENTS.md` explicitly says these are deletion candidates but must not be physically deleted yet.

### Repair

Added `scripts/check-legacy-entrypoints.mjs` and wired it into `npm run qa` as `check:legacy`.

The guard:

1. scans shipping text roots (`index.html`, `app.js`, `styles.css`, `src`, `scripts`);
2. fails if they reference `app-current.js` or `index-current.html`;
3. prints size/SHA-256 and whether legacy/current files diverge;
4. does not delete or rewrite the legacy files.

This converts a silent stale-entrypoint risk into a deterministic QA gate without violating the preservation rule.

## Supabase security checkpoint

Live read-only policy audit shows role/ownership RLS for customer/order/payment/catalog/admin surfaces. Representative controls:

- customer address/profile reads/writes bind to `auth.uid()`;
- order/item/payment snapshot reads bind to the owning profile or explicit manager roles;
- product/variant writes require inventory-manager or owner-admin role;
- payments/refunds writes require payments-manager or owner-admin role;
- user-role mutation requires owner-admin role;
- public product/brand/banner reads are limited to active records.

Security Advisor currently reports:

1. `private.edge_rate_limits`: RLS enabled with no policies. This can be intentional for a private server-only table. Do not add a public policy merely to silence the lint; verify it is accessible only through trusted SECURITY DEFINER/server paths.
2. Supabase Auth leaked-password protection disabled. Enable before relying on password authentication.

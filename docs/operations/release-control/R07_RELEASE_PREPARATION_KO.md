# R07 운영 반영 준비 — 초안

이 문서는 검토용이며 운영 배포나 실결제의 승인이 아니다. 실제 운영 설정·고객 데이터는 변경하지 않았다.

## 확인된 TEST 근거

- R03~R05 인증·권한, TEST 결제와 취소는 각 최종 영수증을 기준으로 검토한다.
- R06 예약 만료 검증과 실제 TEST 결제사·배포 Edge·TEST DB 연속 대사는 완료됐다. 대사는 서울 리전을 명시한 수동 호출이며 자연 발생한 취소 장애의 재현은 아니다. `receipts/R06_20261128_deployed_final.json`.
- 노출됐던 기존 TEST 키 쌍은 사용자 승인 후 공급자 화면에서 제거됐고 새 TEST 키의 서버 일치 및 거래 조회를 확인했다. 다른 TEST 연동에서 기존 보안 키를 사용하는지는 확인하지 못했다. `receipts/R06_20261128_test_key_revocation_observations.json`.

독립 검토에서 확인한 증거의 범위는 다음과 같다.

- R03 고객·관리자 인증과 권한·배송 검증은 이전 배포에서 실행했고, 현재 `7c0c9c4` 배포에는 소스 차이 검토를 거쳐 승계했다. 현재 배포에서 전 과정을 다시 실행한 것은 아니다.
- R04 복구 검증은 이미 완료된 주문의 중복 응답을 받은 후 클라이언트 응답 손실을 모의한 것이다. 최초 승인 도중 자연 발생한 장애는 재현하지 않았다.
- R05 웹훅은 합성 발송이며 토스가 직접 전송한 알림의 증거가 아니다.
- 새 TEST 키 교체 후 대사 검증은 기존에 처리된 이벤트의 중복 분기를 사용했다. 신규 이벤트 반영 근거는 앞선 R06 서울 리전 실행이다.
- 구 TEST 키는 공급자 화면의 새로고침 후 목록에서 제거된 것을 확인했다. 구 키로 직접 API를 재호출하지는 않았다.

## 운영 전 미해결 항목

1. TEST 기본 도쿄 리전에서 대사 호출이 `API_KEY_ACCESS_DENIED`로 실패했다. 서울 지정 호출은 성공했다. 실제 운영의 Edge 리전·토스 LIVE 키 접근 정책·스케줄러 목적지와 인증을 별도 검토하고, 승인된 범위의 검증 전 자동 대사가 정상이라고 판단하지 않는다.
2. `20260828060000_payment_reconcile_scheduler.sql`에는 운영 함수 URL이 포함되어 있다. TEST에 원문을 실행하지 않으며, 운영 실행 전 실제 대상과 현재 cron·Vault 상태를 검토한다.
3. TEST 회원가입 메일의 429 대응 및 셀프 복구 기능은 미해결이다. 이전 프런트 수정은 메일 발송을 단정하는 문구만 바꿨다.
4. 구 TEST 보안 키 폐기가 영향을 주는 다른 TEST 연동이 있는지 확인한다. 운영 키 노출이나 교체를 추정하지 않는다.

## 반영·복구안의 작성 조건

- 최종 후보 SHA, CI, PR 변경점, 운영에서 현재 적용된 DB migration·Edge 함수·설정·스케줄을 실측해 변경 목록을 확정한다. 예전 보고서의 상태를 현재 사실로 간주하지 않는다.
- 운영 데이터 백업과 복원 가능 범위, 프런트/Edge 이전 버전 재배포, DB 호환성과 비가역 migration의 별도 복구 절차 및 담당자를 확인한다. 백업이나 복원 시험을 수행했다고 주장하지 않는다.
- 실제 상점 담당자의 결제·배송·환불·장애 대응 준비 및 키 보관, 알림 수신, 인계 담당자를 확인한다.
- 운영 반영 범위와 시간, 자동 배포 영향, 승인된 실결제·취소 한도를 구체화한 뒤 별도 승인을 받는다. TEST 승인으로 운영 변경을 수행하지 않는다.

R07은 독립 증거 검토와 운영 상태·복구 가능성 확인이 끝날 때까지 PENDING이다.
